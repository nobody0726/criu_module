# A8 问题与解决方法复盘

## 背景

A8 的目标是把 A7 的 process closure 从“多个独立进程”提升到“能保留跨进程共享资源”的镜像：

- `CLONE_FILES` 共享 fd table；
- 跨进程共享的 `struct file`；
- 跨进程 pipe / UNIX stream socket；
- 匿名 `MAP_SHARED` shmem；
- SysV shm 可行性判断。

实现仍遵循既定边界：内核只输出 little-endian TLV snapshot，userspace converter 负责生成 CRIU protobuf/images，真实 restore 继续用 CRIU。

## 主要问题与修复

### 1. fd table 不能按 pid 命名

问题：A3-A7 阶段单进程/弱共享场景中，`fdinfo-$pid.img` 很容易“看起来可用”。但 A8 中两个进程可能有同一个 `files_struct`，此时 CRIU 语义要求 `ids-$pid.img.files_id` 相同，并共同引用 `fdinfo-$files_id.img`。

解决：内核按真实 `files_struct *` 分配 `files_id`；converter 按唯一 `files_id` 分组，只输出一份 `fdinfo-$files_id.img`。

### 2. 跨进程 file object 必须全 closure 去重

问题：fork 后两个进程不同 fd table 中的 fd 可以指向同一个 `struct file`。如果 converter 为它们生成两个 CRIU file id，文件 offset、pipe/socket endpoint 等共享关系会断。

解决：A8 将 file object map、emitted file map、pipe/socket map 提升为 dump transaction 级别；converter 合并全局 file table，并按 `object_id` 检查 path/flags/offset 冲突。

### 3. UNIX socket restore 依赖全局 fd 聚合

问题：早期实现只在 process view 中查找 fd，导致跨进程 UNIX socket object 能被 dump 出来，但 restore 时找不到对应 file item。

解决：A7/A8 converter 在生成 UNIX socket images 前，把所有 process-scoped fd records 聚合到 closure-wide IPC model。

### 4. `criu restore` 返回 0 不是完成标准

问题：A3 已经踩过“restore 返回 0 但进程没活/行为不对”的坑。A8 的共享 fd 和 shmem 更容易出现这种假阳性。

解决：guest gates 必须检查：

- root/child PID 存活；
- 跨进程行为 marker；
- guest `dmesg` 无 `BUG/WARNING/Oops/refcount/KASAN`；
- 对 shmem 还要检查 payload 近似单份，而不是每进程一份。

### 5. shmem pagemap 不能把 raw pages 追加进 pagemap 文件

问题：第一次真实 shmem restore 失败，CRIU 日志显示：

```text
do_pb_read_one: Can't allocate ... bytes
Can't restore shmem content
```

原因：converter 把 raw page bytes 像 `pipes-data.img` / `sk-queues.img` 那样追加在 `pagemap-shmem-$shmid.img` 后面。CRIU 的 page-xfer 模型不是这样：`pagemap-shmem-$shmid.img` 只保存 pagemap protobuf，真实页内容在 `pages-$pages_id.img`，其中 `pages_id` 来自 pagemap head。

解决：converter 为 shmem 生成：

```text
pagemap-shmem-$shmid.img   # pagemap_head + pagemap_entry
pages-$pages_id.img        # raw page payload
```

并让 contract 直接检查 `pages-$pages_id.img` 中 payload 只出现一次。

### 6. shared VMA 必须带 CRIU 的 `VMA_ANON_SHARED` status

问题：仅设置 `vma_entry.shmid` 不够。CRIU restore 侧通过 VMA status 判断是否进入 `add_shmem_area()`。

解决：converter 在 `VMA_CLASS_ANON_SHARED` 时设置 `VMA_ANON_SHARED` status bit，同时保留 `MAP_SHARED|MAP_ANONYMOUS` flags 和 per-process virtual address。

### 7. SysV shm 不应复用匿名 shmem 简化路径

问题：SysV shm 不只是“一个 inode + 一份内容”。完整 restore 还需要 IPC shm metadata、权限、namespace 关系、attach chunk 顺序等。外置模块当前没有安全建模这些信息。

解决：A8 feasibility gate 使用真实 SysV shm fixture 验证当前 dump-tree 明确失败，并记录为：

```text
A8_SYSV_SHM: UNSUPPORTED_RECORDED
```

这比生成不完整镜像安全。

## 验证结果

已通过的核心 gate：

```text
A8_SHARED_FDTABLE: PASS
A8_CROSS_IPC: PASS
A8_SHMEM_CONTRACT: PASS
A8_FD_CROSS_RESTORE: PASS
A8_SHMEM_CROSS_RESTORE: PASS
A8_SYSV_SHM: UNSUPPORTED_RECORDED
```

发布前回归还通过了：

```text
CI_RESULT: PASS
A4_CROSS_RESTORE: PASS
A5_CROSS_RESTORE: PASS
A6_CROSS_RESTORE: PASS
A7_CROSS_RESTORE: PASS
```

其中 `criu-field-compare` 发现 A8 后旧的 A3 严格 golden diff 会把新增的
`files_id`、signal/task IDs、VMA status 和 page-run 展开误报为回归。默认门禁已
改为检查所有模块镜像都能被 `crit` 解码且包含非空 entries；需要逐字段诊断时仍可
显式设置 `A3_FIELD_COMPARE_STRICT=1`。

另外，Lima 当前 `/tmp` 可能被挂成只读。`a8-smoke.sh` 使用
`/run/user/$uid` 作为 `TMPDIR`，`run-qemu.sh` 也尊重该变量；QEMU staging 会在
Lima 本地目录重建 converter、kernel module 和 `tests/progs`，并把 fixture 权限
规范为 `0755`，避免 9p 路径中的 Mach-O、缺少测试二进制或 CRIU mode 校验误报。

环境仍按 A3 复盘执行：

- macOS 只做编辑/Git/编排；
- Lima `criu-dev` 构建 converter 和 kernel module；
- Linux 5.10.29/aarch64 QEMU guest 做 `insmod`、dump、converter、真实 CRIU restore；
- guest restore 使用 `/tmp` 本地目录，避免 9p 权限/语义问题。
